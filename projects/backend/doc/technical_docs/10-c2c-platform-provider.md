# C2C Platform Provider

## 目标

币安和欧易使用同一套订单发现、支付前复核、支付执行、平台付款确认与恢复流程。业务模块只依赖 `C2cPlatformClient`；具体客户端只负责外部协议，不参与业务状态决策。

## 统一调用链

```text
商家账号 + 生效凭据
  -> C2cPlatformCredentialFactory
  -> C2cPlatformClient
  -> BinanceC2cClient | OkxWebPrivateClient
  -> C2cBuyOrderSummary / C2cBuyOrderDetail
  -> 同步、自动支付、批次、15 秒恢复任务
```

以下行为对两个平台一致：

1. 凭据、订单和支付记录同时受 `tenantId`、`merchantId` 约束。
2. 只接收买币订单；方向缺失或为卖币时不进入付款流程。
3. 列表按成功游标、重叠窗口和上游原始分页继续扫描，再逐笔查询详情。
4. 统一归一化订单号、状态、金额、币种、收款方式、收款账号、收款人、实名和付款截止时间。
5. 付款提交前重新查询详情，并核对锁定支付方案、金额、币种、收款资料、付款方式和截止时间。
6. 资金成功后先查询平台状态，仅待付款订单执行标记；已付款或已完成订单幂等收口，取消、过期或申诉订单进入资金异常。
7. 标记付款后再次查询平台状态。支付订单资金状态始终保持 `SUCCESS`；平台确认使用独立的 `PENDING / PROCESSING / FAILED / SUCCESS`。固定 15 秒恢复任务只查询超时的 `PROCESSING`，不重复提交资金请求或盲目重试平台标记。
8. 订单来源不参与 Provider 选择；Provider 由商家账号和订单平台决定。

## 能力矩阵

| 能力       | Binance    | OKX Web Private | 处理规则                                                                 |
| ---------- | ---------- | --------------- | ------------------------------------------------------------------------ |
| 连接测试   | 支持       | 支持            | 统一调用一页订单列表                                                     |
| 买单列表   | 支持       | 支持            | OKX 拉取 pending 后本地过滤 BUY，按原始页继续翻页                        |
| 订单详情   | 支持       | 支持            | 统一返回 `C2cBuyOrderDetail`                                             |
| 标记付款   | 支持       | 支持            | Binance 使用数字 `payId`；OKX 使用无精度损失的 `receiptAccountId` 字符串 |
| 标记前风控 | 无独立请求 | 支持            | OKX Adapter 内执行，异常按既有流程记录并继续，明确风险提示则阻断         |
| 付款凭证   | 不需要     | 可配置          | OKX 默认跳过；显式关闭跳过时必须取得真实回单并上传                       |
| 自动申诉   | 支持       | 不支持          | OKX 无完整真实请求样本，能力关闭且不猜测 URL                             |
| 报表订单   | 不支持     | 不支持          | 当前系统没有接入，能力显式关闭                                           |
| 放币       | 不支持     | 不支持          | 当前系统没有接入，能力显式关闭                                           |
| 平台取消   | 不支持     | 不支持          | 本地作废不等于调用上游取消接口                                           |
| 平台聊天   | 不支持     | 不支持          | 商家聊天配置不代表当前已接入平台聊天协议                                 |
| 卖币订单   | 不支持     | 不支持          | 不进入自动付款状态机                                                     |

## 平台协议差异

Binance 使用 API Key、Secret Key、HMAC 查询签名以及可选 `x-user-id`。订单列表、详情、付款确认和申诉均使用已验证的固定 API 路径。

OKX 使用 Cookie、Authorization 和 PKCS#8 EC 私钥，只允许 `OKX_WEB_PRIVATE` Adapter 访问固定的订单、风控、凭证和付款路径。付款签名原文为固定请求路径、紧凑 JSON 请求体和毫秒时间戳，输出 IEEE P1363 签名。`markAsPaidDisabled`、申诉状态、非买单、凭据失效和付款资料缺失都会阻止自动付款。

## 扩展规则

- 新增 Provider 时必须先实现统一列表、详情、能力声明和参数化契约测试，再接入业务模块。
- 业务模块禁止注入 `BinanceC2cClient` 或 `OkxWebPrivateClient`。
- 新能力只有在官方契约或成功请求样本完整时才能开启；不支持的动作必须通过 capability 明确表达。
- 不得把 Binance HMAC、OKX Cookie 或浏览器签名逻辑移动到业务模块。
