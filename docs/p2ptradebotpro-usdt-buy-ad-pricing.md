# 买 USDT 的广告怎么调价

本文只讲 P2PTradeBotPro 的买 USDT 广告。数字是假设价格，单位统一写成“元”，不代表实时行情。案例假设配置已经在运行中生效。

## 1. 你在做什么，机器人替你做什么

你挂一个广告：“我收 USDT，每个给 7.05 元。”别人把 USDT 卖给你，你付钱。

同行也在收 USDT。谁出价高，通常越容易吸引卖币的人。

**机器人替你看同行报价，再改你广告上的价格。它不会自动转账买币。**

你需要决定两件事：

- **跟哪些同行比**：例如只看某银行、某金额范围的广告。
- **可以参考多高的价**：普通模式由你填写；动态模式由机器人计算。

下面只用一个场景，分三步讲清楚。

## 2. 第一步：普通模式，你自己填价格线

你在机器人里设置：

| 设置 | 填什么 | 是什么意思 |
| --- | --- | --- |
| 价格线 `threshold` | 7.10 | 同行报价超过 7.10，就不跟它 |
| 加价步长 `step` | 0.01 | 在参考同行的价格上高一格 |

机器人查到三家收币同行：

| 同行 | 每个 USDT 愿意付多少 | 机器人怎么处理 |
| --- | ---: | --- |
| A | 7.08 | 没超过 7.10，可以参考 |
| B | 7.09 | 没超过 7.10，可以参考 |
| C | 7.12 | 超过 7.10，排除 |

留下 A 和 B。B 出价更高，所以参考 B。

```text
B 的报价 7.09 + 步长 0.01 = 你的报价 7.10
```

你的广告从 **7.05 改成 7.10**。如果有人卖给你 100 USDT，你按这个广告价需要付 710 元。

下一轮 B 降到 7.07，A 仍是 7.08，机器人就参考 A，把你降到 **7.09**。它会跟着升，也会跟着降。

**注意：这份代码的价格线只检查同行价。** 如果 B 正好报 7.10，仍会通过，然后加 0.01 得到 7.11。它目前不能严格保证你的最终报价不超过 7.10。

## 3. 第二步：打开动态模式，让机器人算价格线

同行选择方法不变。变化的是：**你不用直接填价格线，改为填写想留的价差，机器人根据市场帮你算。**

动态模式会看两张不同的广告列表：

| 列表 | 谁在里面 | 机器人看它干什么 |
| --- | --- | --- |
| 卖币列表 | 别人在卖 USDT，挂着自己的卖价 | 估算市场卖价，计算价格线 |
| 收币列表 | A、B、C 这样的同行在收 USDT | 决定具体跟谁、报多少 |

在币安普通用户页面，这两张列表分别对应“我要买币”和“我要卖币”。都是当前广告，不是已经成交的记录。

### 先从卖币列表取一个价

假设机器人查到的卖价按返回顺序是：

| 位置 | 卖价 |
| --- | ---: |
| 第 1 个 | 7.18 |
| 第 2 个 | 7.19 |
| 第 3 个 | 7.20 |

你填 `price_position=3`，它就拿 **7.20**。意思是“用第三个价格计算”，不是让你的广告排第三。

### 再扣掉你想留的钱

你填：每个 USDT 想留 **0.05 元**，手续费 **0.11%**。

```text
参考卖价              7.20
减去你想留的价差      0.05
减去估算手续费        约 0.008
────────────────────────
机器人算出的价格线    约 7.14
```

准确公式是 `7.20 - 0.05 - 7.20 × 0.11%`，源码保留两位小数，得到 7.14。

### 最后回到收币列表，选择同行

仍然用刚才的同行：A=7.08、B=7.09、C=7.12。

现在价格线从 7.10 变成了 **7.14**。C=7.12 也能参加，而且是三家里出价最高的。

```text
选 C
C 的报价 7.12 + 步长 0.01 = 你的报价 7.13
```

**所以动态模式最终报 7.13，不是直接报计算出来的 7.14。** 7.14 只是判断哪些同行能参加的线；实际出价跟着同行走。

这里的利润只是估算。7.20 是别人的卖币挂价，不能保证你以后也能按 7.20 卖出去。

## 4. 第三步：改一个参数，看看结果怎样变

仍使用同一组同行 A=7.08、B=7.09、C=7.12，参考卖价 7.20，手续费 0.11%，步长 0.01。每行只改变“想留的价差”：

| 想留的价差 `profit` | 算出的价格线 | 哪些同行能参加 | 最终报价 |
| ---: | ---: | --- | ---: |
| 0.05 元 | 7.14 | A、B、C | 跟 C，报 **7.13** |
| 0.08 元 | 7.11 | A、B | 跟 B，报 **7.10** |
| 0.12 元 | 7.07 | 都不能参加 | 通常**保留旧价** |

想留的钱越多，愿意参考的收币价格越低。不是把 `profit` 加到广告价上，而是从参考卖价里扣掉。

最后一行有个代码缺口：没有合格同行时，它通常不改广告。假如之前已经挂着 7.13，可能继续是 7.13，**不会自动改成 7.07，也不会自动下架**。

市场卖价变化也一样：卖价涨，价格线通常升；卖价跌，价格线通常降。下一轮重新看哪些同行能参加。

## 5. 其他常用参数：它改变的是哪一步

下面的银行、金额和时限，是**找同行的条件**，不会自动修改你自己在币安广告上的银行列表或交易限额。

| 你想调整什么 | 参数 | 举例说明 |
| --- | --- | --- |
| 普通模式价格线 | `threshold` | 填 7.10，排除同行 C=7.12；普通买 USDT 填 0 时不限制这条线 |
| 动态模式想留的价差 | `profit` | 填 0.05，代表每个 USDT 留 0.05 元，不是 5% |
| 动态模式手续费 | `binance_fee` | 填 0.11 代表 0.11%；填得越大，算出的价格线越低 |
| 取哪个参考卖价 | `price_position` | 填 3，取返回的第 3 个；没有第 3 个时取最后一个；0 取第 1 个 |
| 出价高一格的间隔 | `step` | 同行 7.09、step=0.01，报 7.10 |
| 查询多大金额的同行广告 | 普通 `filtr`；动态 `strategy_filtr` | 填 5000，查询适合 5000 元交易的广告，不是机器人自动买 5000 元 |
| 查哪些支付方式的收币同行 | `banks` | 查 BankA，可能看不到只支持 BankB 的同行 |
| 查哪些支付方式的参考卖价 | `position_banks` | 从 BankA 改 BankB，参考卖价可能改变，价格线也可能改变 |
| 同行广告的付款时限条件 | `period` | 填 15，会把 15 分钟条件传给平台；具体匹配由平台决定 |
| 是否只看商家 | `publishertype` | 1 只看商家；其他值不限定为商家，参考卖价查询也受它影响 |
| 只跟一个人 | `competitor_nickname` | 填 A，就只看 A，可能报 7.09；A 不在结果里就不跟其他人 |
| 不跟某个人 | `blocked_ads` | 黑名单里有 C，就排除 C，再从 A/B 选择 |
| 排除自己 | `my_nickname` | 填自己的准确昵称，避免把自己当成要加价竞争的同行 |
| 大致多久再看一次 | `delay` | 5 表示循环有 5 秒等待，实际还要加上查询耗时，不是精确每 5 秒更新 |

关于 `step` 多补一句：它按价格格子向上调。同行 7.091、步长 0.01 时，目标是 7.10；不是简单相加成 7.101。步长必须大于 0。

## 6. 有些设置名字容易误导，记住这几项

| 参数 | 当前代码实际情况 |
| --- | --- |
| `strategy_step` | 最终报价仍主要使用 `step`，改这个不代表加价步长跟着改 |
| `strategy_banks` | 主要决定重复查询次数；真正查询同行的支付条件仍是 `banks`；为空时策略循环不执行 |
| `strategy_period` | 没有完整用于查询；同行时限仍主要使用 `period` |
| `strategy_threshold` | 动态价格线的计算结果，下次计算会覆盖，不能拿它当固定上限 |
| `strategy_profit` | 主要用于其他币种；买 USDT 的固定价差用 `profit` |
| `price_precision`、`competitor_select_mode`、最小/最大金额及价格设置 | 没有完整接入买 USDT 的实际调价，不能当作可靠保护 |

如果配置多个支付方式，程序可能重复查同一组同行，再把几次算出的新报价取最小值。例如分别算出 7.13、7.10，最终可能提交 7.10。前面三个例子都假设只有一次有效查询，便于看清基本方法。

## 7. 启停、副广告和保存配置

- `number` 是你自己的广告编号，决定读哪张价签、改哪张价签。填错会影响错误的广告或导致失败。
- 关闭机器人里的自动调价，只是不再安排新的调价任务，不代表币安广告已经下架。
- 副广告通过 `dubl_number` 指定编号，按 `dubl_discount` 跟着主价打折。主价 7.10、系数 0.01，副价为 7.029；它没有重新独立计算利润线。
- 保存配置不代表运行中的所有任务马上用新值，黑名单和启停状态的重启恢复也不完整。要核对实际使用的参数和平台价格。
- 当前 `USDTUSD_BUY` 有币种解析缺陷，可能无法按上述正常流程运行；案例只解释正常买 USDT 分支，不是可直接粘贴的运行配置。

## 8. 你判断结果时，只问三个问题

1. **这一轮价格线是多少？** 普通看 `threshold`；动态看参考卖价扣利润和手续费后的结果。
2. **哪些同行没有超过这条线？** 再排除自己、黑名单和不符合指定昵称的人。
3. **留下的人里谁出价最高？** 在它的价格上向上调一格，就是目标报价。

目标价等于自己的当前价时通常不改；没有候选时通常保留旧价。计算出的目标还需要币安接受更新，才算实际广告价格。
