# ADR-0001：采用多仓库控制平面

- 状态：Superseded by ADR-0002
- 日期：2026-09-09

## 背景

系统以后端 `tpl-backend` 和后台前端 `tpl-frontend` 为开发基础，同时保留 `pfa-pay` 作为 C2C 与 Telegram 领域参考。三个仓库已有独立 Git 历史、包管理配置和构建方式。

## 决策

根目录建立独立的工作流控制平面 Git 仓库，维护 `projects.json`、Skills、协作规则、系统设计和统一命令。三个源码仓库保持独立 Git，并由根 `.gitignore` 排除。

当前沿用已存在的 `templates/*` 路径以避免无收益的大规模移动；项目身份以 `projects.json` 的稳定 ID 为准，不依赖目录名称。`pfa-pay-reference` 明确为只读。

## 原因

- 前后端需要独立提交、发布和回滚。
- 根目录不安装业务依赖，避免 pnpm workspace 相互污染。
- C2C 需求、API 契约和发布顺序仍可在统一入口协同。
- 参考仓库不会被误合并到产品代码，也不会把已发现的安全问题直接带入目标系统。

## 后果

- 跨仓库变更必须分别提交，并明确契约兼容和发布顺序。
- 开始任务前必须读取项目清单并检查各仓库状态。
- 若以后配置新的产品远端，可以在保持项目 ID 不变的情况下调整路径或 remote。
- 只有当发布节奏、依赖管理和源码共享需求高度一致时，才重新评估真正的 monorepo。
